# 自由な文章から手順書に書き換える

SKILL.md の「1. 手順書を用意する」で、ユーザーの文章が決まった形になっていないときに読む。

ユーザーの文章が説明書・メモなど自由な形のときは、次の基準で手順書にする。書き換えたら工程の一覧（工程名と 1 行の要約）をユーザーに短く示してから次に進む（確認待ちは不要。元の文章に無い判断をしたときだけ、その点を添える）。

- **工程の区切り**: 1 工程 = 道具か場所が変わらない一続きの作業。4〜8 個に収める。多すぎるときは同じ道具・同じ場所の工程をまとめ、少ないときは「準備」「仕上げ・確認」を独立させる
- **番号付きの小手順**（1. 2. 3. や ①②）: 1 つの工程の中なら、1 項目 = 1 文にする。多い（4 つ以上）ときは工程を分ける
- **注意書き・警告**（※、注意、Warning、危険）: その作業の工程の最後の 1 文にする（例:「熱いので、やけどに気をつけてください。」）。全体にかかる注意は、冒頭の「はじめに」か末尾の「注意事項」の工程に 3 つまでまとめる。安全に関わる注意は省かない
- **表・数値**（分量表・寸法・設定値）: 読み上げに要る値だけを文にし、細かい一覧は絵コンテで画面の注釈（`Callout`・`PartsList`・`StepNotes`）に回す。数値と単位は元の文章から変えない
- **理由・背景・豆知識**: 動画で見せられないものは、1 工程に 1 文までにするか削る
- **1 文の長さ**: 日本語は 40 字、英語は 20 語くらいまで。長い文は「何を → どうする」で分け、読点で句を区切る
- **読みにくい記号**（℃、mL、cm、%、型番、URL、画面のボタン名「［保存］」など）: 本文は表示用としてそのまま書き、日本語は `script.json` の `speak` を読みやすくする（読みはカタカナで書く。SKILL.md の手順 2 の最後）。URL は読み上げず、画面の注釈に回す
- **元の文章に無いこと**: 手順・数値・道具を足さない。手順が抜けていて動画にできない、または読み方が分からない数値や略語があるときだけ、ユーザーに確認する
