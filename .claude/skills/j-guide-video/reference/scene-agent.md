# 工程担当サブエージェントへの指示（テンプレート）

> 工程全体を Swift の visual で書くとき（キューで書けない動きが多いとき）の手順。ふだんはキュー（[cue.md](cue.md)）で書く。

[implementation.md](implementation.md) の「流れ」の 4 で、工程ごとのサブエージェントに渡すプロンプト。`{…}` を埋めて Agent ツールの `prompt` にそのまま入れる。1 体に 1 工程（工程が 9 つ以上なら 2 工程ずつ）を担当させる。

````markdown
あなたは手順動画（Swift の描画 DSL）の 1 工程のアニメーションを実装する担当です。
ほかの工程は別の担当が同時に実装しています。自分の担当ファイル以外は編集しないでください。

## 担当
- プロジェクト: {プロジェクトの絶対パス}
- 工程: {工程番号 (0 始まり)} 「{工程名}」
- 実装するファイル: visuals/{Visual}.swift（今は仮実装。`func {Visual}(_ props: Props)` を本実装に置き換える）
- 型: {部屋 / 画面操作 / 手元俯瞰 / 組み立て説明書}{、縦型}
- jgv コマンド: {skill のパス}/bin/jgv

## 絵コンテ全体の前提（storyboard.md の冒頭）
{storyboard.md の最初の「## 」より前の部分。共通の部品・状態のそろえ方}

{script.json のこの工程の lines を「0: …」「1: …」の形で}

## 絵コンテ（storyboard.md のこの工程の節）
{storyboard.md から該当する節をそのまま貼る。「始まりと終わりの状態」を含める}

## 先に読むもの
1. {プロジェクトの絶対パス}/out/brief.md … この型に必要なルールと API、この動画の共通部品（shared.swift・props.swift）とユーザーのライブラリの部品（parts。この動画で使うファイルはシグネチャ、ほかは名前だけ）、SVG の素材（assets。レイヤーの名前と持つ所）の一覧。**最初にこれだけを読む**（implementation.md・visual-kit.md の全文は読まない）
2. 必要になったときだけ:
   - {skill のパス}/reference/props-catalog.png … kit の道具の見た目（道具を選ぶとき）
   - {プロジェクトの絶対パス}/visuals/shared.swift・props.swift の中身、kit のソース（brief.md の冒頭に書いてあるパスの JGVKit） … brief.md の一覧で分からないとき
   - 参考になる実例: {似た実例の visual のパス。無ければ省略} … 動きの書き方に迷ったとき

## 守ること
- 編集してよいのは visuals/{Visual}.swift だけ。shared.swift・props.swift・script.json・assets・kit・parts は編集しない
  - 足りない道具や共通化したい処理は、自分のファイルの中に `private` で書き、報告の「共有に移す候補」に書く（すべての visual が同じモジュールなので、`private` を付けないとほかの担当の名前とぶつかる）
- brief.md の共通部品・ライブラリの部品にある道具や動きは、描き直さずにそのまま呼ぶ（同じモジュールなので import は要らない）
- `jgv tts`・`jgv dev` と、`--scene` を付けない `jgv snapshots` / `jgv render` は実行しない（ほかの担当とファイルを取り合い、ほかの担当の書きかけのファイルでビルドが止まる）
- **絵コンテの「始まりと終わりの状態」を必ず守る**。前後の工程は別の担当が、この状態を前提に作っている。工程の最初のフレームは「始まり」、最後のフレームは「終わり」の見た目にする（途中で置いた道具を最後に消さない、外した手袋を勝手に戻さない、など）
- タイミングは `n.at()` / `n.atPhrase()` で取り、秒数を直書きしない
- 片付ける・置く・手を戻すなど「終わり」の状態へ向かう動きは、工程の最後の 0.5 秒前（`n.durationInFrames - n.fps * 0.5`）までに終える（確認用の静止画の右端はこの時刻）。最後の行の読み終わりからこの時刻までは約 0.4 秒しかないので、最後の行を読んでいる間に始める
- 動きの計算は kit の `easeAt` `dropAt` `track` `zigzag` `clock`、注ぐ `pourFrom`、プラグの `unplug` / `plugIn`、画面の `phoneSpace` / `browserSpace`、シーンの型（`PrepareItems` `NoteCards` `BeforeAfter` `SummaryList`）を使い、同じものを書き直さない
- kit の関数と同じ名前のローカル変数（`path` `rect` `g` `line` `text` など）を作らない（kit の関数が隠れてコンパイルエラーになる）。型チェックが遅いと言われた式は、途中の値を `let` に分ける

## 確認（最大 3 回まで直してやり直す）
```bash
cd {プロジェクトの絶対パス} && {skill のパス}/bin/jgv snapshots --scene={工程番号} --phrases
```
この工程の visual と補助ファイルだけでビルドする（ほかの担当が編集途中のファイルのエラーでは止まらない。kit のビルドは全工程で共通なので数秒で終わる。ほかの担当がビルド中なら、jgv が終わるのを待ってから順に進む（何も出ずに待つことがある）。コンパイルエラーはファイル名と行番号付きで出るので、自分のファイルを直してやり直す。

`out/snapshots/scene-{工程番号}/sheet.png` を Read して、次を確認する（左端が工程の最初、右端が工程の最後の 0.5 秒前＝拡大カードが縮む前、間が句ごと。自分で別のフレームを切り出す必要はない）。一覧で小さくて見えない所（点線・注釈の文字・手と持ち手の位置）は、同じフォルダの 1 コマずつの静止画 `00-CC.png`（書き出したときに表示される各行の頭の番号。`00-03.png` = 左から 4 コマ目。動画の半分の大きさ）を Read する:
- 左端と右端が、絵コンテの「始まりと終わりの状態」どおりか
- 句の内容と画面の動作が合っているか、手が道具の持ち手に付いているか、道具が宙に浮いていないか
- 見出し（左上）と字幕バー（下）に重なっていないか、文字が読めるか（`style.notes` が `false` なら、説明の文字が出ていないか）
- 止まった画面になっていないか

句のコマは、句の読み始めから 0.35〜0.9 秒後の 1 枚だけ。句の途中の一瞬（道具を取る・置く瞬間など）を確かめるときは、工程の始まりからの秒を指定して撮る（句ごとの秒は brief.md の「各工程の行と句の番号」にある）:
```bash
cd {プロジェクトの絶対パス} && {skill のパス}/bin/jgv snapshots --scene={工程番号} --at=1.5,2.0,2.5
```
出力は `out/snapshots/scene-{工程番号}/at/` の `00.png`〜 と `sheet.png`（`--phrases` の静止画と一覧はそのまま残る）。

## 報告（最後のメッセージ。日本語で 200 字程度）
- 実装した内容（句ごとの動きを 1 行ずつ）
- 確認の結果（直したこと、残っている気になる点）
- 共有に移す候補（無ければ「なし」）
````

## メインの担当が埋めるときの注意

- 起動する前に `jgv brief {プロジェクトの絶対パス}` で `out/brief.md` を作る（shared.swift・props.swift を変えたら作り直す）。担当が implementation.md・visual-kit.md・共通部品のソースを全部読むと、その分が毎ターン読み直されて、トークンが数倍になる
- 起動する前に `jgv tts` を実行しておく（`.jgv/timeline.json` が要る。担当は実行しない）
- 実例は `demo/` の同じ型・似た動作の visual を 1〜2 ファイル指定する（リポジトリに無ければ省略）
- 共通の土台（shared.swift・props.swift・画面の状態の struct と描画関数）は、サブエージェントを起動する前にメインで作り、`jgv snapshots` が通ることを確かめておく。担当どうしで同じ道具を別々に描くのを防ぐ
- 絵コンテの節に「始まりと終わりの状態」が無ければ、起動する前に書き足す。並列で作ったときの工程のつながりの崩れ（道具が消える・表示がばらばら）は、ほとんどがここから起きる
- 全員の報告がそろったら、`jgv snapshots --seams` でまとめて確認する（visual の登録表はビルドのたびに作り直される）。担当が `private` で書いた同じ道具が複数あれば shared.swift・props.swift に移す
