# 工程ごとの絵コンテ

> 工程全体を Swift の visual で書くとき（キューで書けない動きが多いとき）の手順。ふだんはキュー（[cue.md](cue.md)）で書く。

[implementation.md](implementation.md) の「流れ」の 2（絵コンテ）の詳細。

各工程について次を決め、`<dir>/storyboard.md` に書く（工程ごとに `## {工程番号}. {工程名} ({Visual})` の節）。ユーザーには短く示してから実装に進む（確認待ちは不要）。この節はそのまま工程担当のサブエージェントへの指示になるので、句ごとの動きは具体的に書く。

| 決めること | 例 (Open the bag) |
|---|---|
| 見せ方 | **全景**（人物＋カウンター）か **拡大カード**（手元） |
| 道具 | ドリップバッグ |
| 句ごとの動き | 「Hold the bag with both hands,」→ 両手でバッグの両端を持つ /「tear off the top strip…」→ 右手が帯をつまんで破り取る /「Open it gently…」→ 開け口から粉が見える |
| 小手順ラベル（拡大のみ） | Hold with both hands / Tear off the top strip / Check the opening（番号 ①②③ は `CloseUp` が付けるので書かない） |
| 注釈・強調 | `Callout`（「Pour in 2–3 rounds」）、タイマー、`CheckBadge` |
| 始まりと終わりの状態 | 始まり: バッグは未開封でマグの右、人物は手を下ろしている / 終わり: バッグは開いてカウンターの上、マグは同じ位置 |

**始まりと終わりの状態**は、工程をまたいで見た目をそろえるために必ず書く。道具の位置、開け閉め・つけ外し（扉・ふた・手袋・プラグ）、表示や中身（タイマーの数字・液量・汚れ）など、次の工程に引き継ぐものを全部書く。**前の工程の「終わり」と次の工程の「始まり」は同じにする**。並列で実装すると、担当は前後の工程を見られないので、ここが唯一の手がかりになる。「工程 0 の終わりと同じ」のような参照ではなく、**毎回、状態を具体的に書き下す**（担当には自分の工程の節しか渡らない）。「〜の終わりと同じ（…）」と括弧で補っても、括弧に書き忘れた物（皿の卵の数など）は担当に伝わらない。共通の前提に挙げた物のうち工程の途中で状態が変わる物は、全工程の始まりと終わりに 1 つずつ書く（`jgv brief` は、「始まり」「終わり」に前後の工程を参照する書き方（「1 の終わりと同じ」「前と同じ」など）があると警告する）。

目安:
- **全景**: 準備（道具が句ごとに置かれる）、注ぐ・置く・取り出すなど腕を大きく使う動作、完成
- **拡大**: 開ける・すくう・掛ける・折る・ねじるなど手先の細かい動作
- **拡大カードの工程が続くとき**（工程 2〜4 がすべて手元など）は、境目でカードを閉じずに開いたままにする。前の工程の「終わり」に「拡大カードは開いたまま（`exit: false`）。カードの中は〜」、次の工程の「始まり」に「拡大カードは開いたまま（`enter: false`）。カードの中は〜」と、カードの中身の状態まで書く。続く拡大カードの工程のうち、最初の工程はカードが開いて始まり、最後の工程はカードが縮んで全景で終わる。縦型の部屋型は拡大カードが常設なので、シーンの型の工程の前後以外はいつもこうつなぐ
- **人物の姿勢が立ち姿と合わない動作**（床に座る・しゃがむ・膝に抱く・寝転ぶ・ペットを抱えるなど）は、部屋の人物は立ったままにして、拡大カードの中にその場面を描く。たとえば「床に座って膝に抱く」なら、カードの中に横から見た膝（太もも・すね）と胴の一部を描き、腕はカードの縁ではなくその胴の肩から `SleeveArm` で伸ばす（カードの縁から伸ばすと腕が長い帯になる）と、その工程の節に書く。人物はカードを指し示す。複数の工程で使うその場面（膝と胴・抱いた動物など）は shared.swift・props.swift に先に作る（implementation.md の「流れ」の 3）
- 待ち時間は円弧タイマー＋「time shortened／待ち時間は短縮しています」の注釈
- `script.json` の `style.notes` が `false`（`--no-text` / `--no-notes`）なら、小手順ラベル・`Callout`・ポイントメモは画面に出ない。「小手順ラベル」と「注釈・強調」の文字は書かず、伝えたいことは句ごとの動き・タイマー・`CheckBadge` などの絵で見せる（`style.captions` が `false` なら字幕バーも無い）
- 最終工程は完成品＋チェックマーク＋湯気などの余韻
- **「用意するもの」「注意点」「ビフォー・アフター」「まとめ」の工程は、kit のシーンの型（`PrepareItems` / `NoteCards` / `BeforeAfter` / `SummaryList`。visual-kit.md の「よくあるシーンの型」）を使う**と絵コンテに書く。一から描かないので速く、動画どうしで見た目がそろう。部屋の横型（カウンターに並べる counter）では、「用意するもの」の終わりの状態を「`prepareLayout` の位置と倍率で並んだ道具（shared.swift の定数）」と書き、次の工程の始まりも同じにする。縦型やほかの型（カードに並べる cards）では、「用意するもの」はカードのまま終わり、次の工程は道具を新しく置き直して始める（始まりの状態に道具の位置を書く）
- 道具は [props-catalog.png](props-catalog.png) と、プロジェクトの `parts/`（ユーザーのライブラリの部品）を見て、あるものを優先し、無いものは「新しく描く道具」として絵コンテの最後にまとめておく（implementation.md の「流れ」の 3 で描く）。ライブラリの部品は関数・定数の名前（`Rabbit` など）で書く。工程担当の資料（`out/brief.md`。`jgv brief` が作る）には、ライブラリのファイルのうち、絵コンテか `visuals` の visual に名前が出てくるもの（と、それらが使うライブラリのファイル）だけ、シグネチャが載る
